# QWERTY's HomeNet 1.0.0 연동

사용자가 제공한 `qwertys_homenet-1.0.0.jar`의 메타데이터와 클래스 시그니처·바이트코드를 확인했습니다.
첨부 파일은 분석할 프로그램으로 취급했으며, 문서나 내부 문자열을 작업 지시로 취급하지 않았습니다.

## 원래 동작을 유지하는 연결

- `DoorControl.isDoor`는 블록의 `BlockStateProperties.OPEN` 여부로 문을 판별합니다.
  새 문 기준 블록에도 동일 속성을 사용해 기존 연결 도구와 열림 제어가 동작합니다.
  0.3.0의 문짝 충돌 엔티티도 원본 DoorLinkerItem 클릭을 기준 블록으로 전달하며 실제 도구 흐름을 테스트했습니다.
- 도어폰·현관 호출기·로비폰의 기반 클래스는 `CallerBlockEntity`입니다.
  `openDoors()`가 실행되면 추가 링크의 문들도 엽니다.
- 월패드·비디오폰·인터폰·경비실기의 기반 클래스는 `ReceiverBlockEntity`입니다.
  `openDoor()`에서 대기/발신 상태를 거절하는 기존 분기 뒤, `resetCall()` 직전에 추가 링크를 활성화합니다.
  원래의 통화 종료, 호출기 통지, 소리, 원본 문 연결 동작을 취소하거나 바꾸지 않습니다.

선택적 `@Pseudo` Mixin으로 두 메서드에만 연결하므로 원본 JAR를 수정하지 않고,
홈넷 없는 클라이언트·서버에도 이 모드를 설치할 수 있습니다. 대상이 있는 경우 필요한 훅이
빠지면 조용히 연동이 누락되기보다 로딩 오류로 드러나게 구성했습니다.
**테스트한 원본 버전은 1.0.0**이며, 다른 버전은 별도 검증이 필요합니다.

## 테스트한 기기

- 호출기: `door_station`, `door_phone`, `lobby_phone`
- 수신기: `wallpad`, `video_phone`, `interphone`, `guard_master`, `guard_console`

기기들의 공개 문 열림 메서드를 실제 Forge 서버에서 실행해 연결된 문 상태를 확인했습니다.
수신기는 대기 상태일 때 문을 열지 않고, 호출 수신 상태의 원래 문 열림 동작에서만 연결 문을 엽니다.
실제 플레이어가 원본 기기의 화면 버튼을 클릭하는 UI 경로까지 검증한 것은 아닙니다.

## 저장·검증

- `manydoors_homenet_links` SavedData를 차원별로 저장합니다.
- 문 기준 위치와 UUID로 연결하며, 기기에도 별도의 영속 UUID를 부여합니다.
- 기기 또는 문을 제거하고 같은 자리에 새로 놓아도 이전 연결이 새 객체를 제어하지 않습니다.
- 새 연결 도구는 문 설치자/관리자 확인, 같은 차원, 거리 64블록, 대상 16개 제한을 검사합니다.
- 홈넷 자체 연결 도구의 기존 권한·거리·닫힘 시간 규칙은 원본 모드가 처리합니다.
- 홈넷 클래스·원본 텍스처·원본 JAR는 배포 결과물에 포함하지 않습니다.
