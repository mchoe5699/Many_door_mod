# Many Doors — Minecraft 1.20.1 / Forge

크기·두께·개방각을 설정하는 **33종의 문**, 문 연결 도구, 열림 버튼·센서와
**QWERTY's HomeNet 1.0.0** 연동을 제공하는 모드입니다.

## 게임에 설치

1. Minecraft **1.20.1**, Forge **47.4.0**, Java **17**을 준비합니다.
2. `build/libs/manydoors-0.3.0.jar`를 클라이언트와 서버의 `mods` 폴더에 넣습니다.
3. 홈넷 연동을 사용하려면 원본 `qwertys_homenet-1.0.0.jar`도 양쪽에 넣습니다.
   홈넷 모드가 없어도 문·버튼·센서 기능은 사용할 수 있습니다.

원본 홈넷 JAR는 이 모드에 포함하거나 재배포하지 않습니다.

## 문과 기기 연결

크리에이티브 인벤토리의 **다양한 문** 탭에 모든 문과 도구가 있습니다.
서바이벌에서는 석재 절단기에 목재·철괴·유리를 넣고 원하는 문 종류를 선택합니다.
버튼·센서·도구에는 작업대 제작법도 있습니다.

1. 문 기준 블록 자리만 비워 문 아이템을 배치합니다. 움직이는 문짝은 주변 벽을 통과합니다.
2. **문 설정 도구**로 문을 클릭해 너비·높이·두께·최대 개방각·모드·자동 닫힘을 입력합니다.
3. **문 연결 도구**로 문을 클릭한 다음 홈넷 기기, 열림 버튼 또는 센서를 클릭합니다.
4. 같은 문과 기기를 다시 연결하면 해당 연결을 해제합니다.
5. 연결 도구를 들고 웅크린 채 기기를 클릭하면 그 기기의 문 연결을 초기화합니다.
   문을 웅크려 클릭하면 도구의 문 선택만 초기화합니다.

문이 열린 상태에서도 움직인 문짝을 클릭할 수 있습니다. 기기 하나당 최대 **16개 문**,
거리 **64블록**, 같은 차원에서 연결합니다. 설치자 또는 관리자가 설정과 새 링크를 변경합니다.
문을 부수고 새로 놓으면 새 식별자가 발급되어 이전 링크로 새 문을 열 수 없습니다.
언로드된 문을 연결하거나 제어하려고 강제로 청크를 로드하지 않습니다.

| 모드 | 문 직접 클릭 | 일반 버튼·센서·레드스톤 | 홈넷·비상 버튼 |
| --- | --- | --- | --- |
| 수동 | 여닫기 | 무시 | 열림 |
| 자동 | 무시 | 열림 | 열림 |
| 수동 + 자동 | 여닫기 | 열림 | 열림 |

홈넷 수신기에서는 기존 통화 및 문 열림 가능 조건을 유지합니다. 대기 상태의 월패드에서
새 링크를 연결했다는 이유만으로 문이 열리지는 않습니다.

## 설정 범위

- 너비·높이: 각각 **1–6블록**, 정수로 입력합니다.
- 두께: **0.0625–0.5블록**, 소수로 입력합니다.
- 최대 개방각: **1–180도**, 소수로 직접 입력합니다. 한짝·양개 여닫이와 피벗문에 적용합니다.
- 한짝 여닫이문: 좌우 경첩 방향을 선택합니다.
- 자동 닫힘: **0–60초**. 0은 자동 닫힘을 끕니다. 직접 클릭으로 연 문은 다시 클릭해 닫습니다.
- 동작 센서: 설정 도구로 기기를 클릭해 감지 범위 **1–8블록**을 입력합니다.
- 벽 기기 위치: 좌우·높이 각각 **−0.45–0.45블록**, 돌출 **0–0.3블록**, 크기 **0.4–1.4배**.
  버튼과 동작 센서는 벽의 옆면에 붙여 배치합니다. 발판 센서는 바닥에 놓습니다.

접이문은 접이 구조에 맞는 85도 접힘을 사용하고, 회전문은 약 36도/초로 회전하다 해제 시 멈춥니다.
롤 셔터·승강문·차고문은 각각의 이동 구조를 사용합니다.

문 이동 경로에는 블록을 배치하지 않습니다. 문 주변에 벽·천장·장식을 놓을 수 있고,
문은 벽 속으로 통과해 열리고 닫힙니다. 충돌·클릭 영역은 저장되지 않는 보조 엔티티로 계산하며,
그 엔티티는 블록 설치를 막지 않습니다. 문 기준 블록 자체와 로비폰형 문에 실제로 존재하는 고정 기둥은 점유됩니다.
크리에이티브에서는 문짝을 타격해, 서바이벌에서는 웅크린 채 문짝을 타격해 문을 철거합니다.
0.2 월드를 열면 기존 숨은 이동 부품을 자동으로 정리하고 문 설정·연결 UUID는 보존합니다. 설정과 연결은 월드 저장 데이터에 남습니다.
움직이는 문과 충돌 판정을 함께 계산하고, 닫히는 문에 살아 있는 엔티티가 끼면 다시 열립니다.

## 기기

| 기기 | 기능 |
| --- | --- |
| 문 열림 버튼 | 연결된 문들을 열고 자동 닫힘 타이머를 갱신 |
| 동작 감지 센서 | 주변의 살아 있는 엔티티를 감지해 열림 유지, 관전자 제외 |
| 발판 센서 | 위에 선 엔티티를 감지해 열림 유지 |
| 문 상태 센서 | 연결된 문 중 열림 명령 상태(`OPEN`)인 문이 있으면 레드스톤 15 출력 |
| 문 상태 표시등 | 열림 명령 상태를 빛과 레드스톤으로 표시 |
| 비상 문 열림 버튼 | 수동 모드도 원격으로 열기 |

기본 홈넷 문 연결 도구도 **문 기준 블록**의 `OPEN` 속성을 인식합니다.
문짝의 다른 부위를 포함해 쉽게 연결하려면 이 모드의 문 연결 도구를 사용하세요.
홈넷의 자체 연결 도구를 쓰는 경우 닫힘 시간은 홈넷의 기존 동작을 따릅니다.

## 커스텀 디자인

문 설정 화면의 **커스텀 디자인**에서 문 표면을 직접 그릴 수 있습니다.
색상은 `#RRGGBB`, 브러시는 1·2·4·8픽셀입니다. 왼쪽 드래그로 그리고 오른쪽 드래그로 지웁니다.
**사진 불러오기**에서 PNG/JPEG를 선택하거나 파일을 편집 화면에 드래그해 넣으세요.
사진은 16 MB 이하로 제한하며, 64×96픽셀 표면으로 변환합니다. 적용 후 서버 월드에 저장되어
다른 플레이어에게도 표시됩니다. **기본 디자인 복원**으로 원래 외형을 복원합니다.
이 기능은 표면 이미지 편집이며 임의의 3D 모델이나 충돌 구멍을 만드는 기능은 아닙니다.

## 로비폰 설치형 자동문

새 **로비폰 설치형 자동문**에는 고정 기둥과 자동 양개 유리문이 있습니다.
기둥 앞쪽 옆면에 원본 홈넷의 **로비폰**을 직접 설치하고 문 연결 도구로 연결하세요.
로비폰을 모드에 내장하거나 복제하지 않으며 원본 홈넷이 필요합니다.
이 문은 기본 너비 3블록 중 1블록이 기둥, 나머지 2블록이 유리문입니다. 너비는 최소 2블록입니다.
기둥은 실제 고정 블록이므로 그 내부에 다른 블록을 놓을 수 없습니다. 문짝 이동 경로는 비어 있습니다.

[실제 게임 화면](docs/SCREENSHOTS.md)에서 센서·버튼·설정·사진 편집과 로비 자동문을 확인하세요.

## 문 종류와 홈넷 동작

[문 종류 목록과 조사 출처](docs/DOOR_CATALOG.md), [홈넷 연동 구현](docs/HOMENET.md)을 참고하세요.
현관문 재질·패널·문양은 외형 변형입니다. 방음·기밀·인증된 방화 성능 같은 현실 기능은 시뮬레이션하지 않습니다.
33종의 건축용 문을 구현했으며 차량·항공기·특수 산업용 문까지 모든 문을 구현했다는 뜻은 아닙니다.

## 0.3.0 업데이트

클라이언트·서버에서 0.2.0 JAR를 0.3.0 JAR로 교체하세요. 네트워크 형식이 바뀌어 같은 버전을 사용해야 합니다.
구형 문 주위의 숨은 부품 정리, 이동 영역 블록 설치, 벽 통과, 벽 부착 기기, 위치·디자인 편집이 포함됩니다.
센서·버튼은 첨부 사진을 기준으로 둥근 몸체·금속 테두리·창·링·홈·문구를 3D로 구현했습니다.
재질의 실제 광학 반사까지 사진과 동일하게 재현하는 렌더러는 아닙니다.

## 개발·검증

클라우드의 JDK·Gradle 캐시는 저장소 밖에 있습니다.

```bash
/workspace/.tools/cloud-gradle build
/workspace/.tools/cloud-gradle runGameTestServer
/workspace/.tools/cloud-gradle -PwithoutHomeNet runGameTestServer
```

일반 로컬 개발에서는 Java 17을 `JAVA_HOME`에 지정하고 저장소에서 `./gradlew build`를 실행합니다.
홈넷 연동 개발을 하려면 원본 JAR를 `libs/qwertys_homenet-1.0.0.jar`에 넣습니다.
이 경로는 Git에서 제외되어 있습니다. 없어도 컴파일되며, 있으면 ForgeGradle이 개발용 이름으로 리매핑합니다.

- 개발 클라이언트: `./gradlew runClient` (그래픽 환경 필요)
- 일반 개발 서버: `./gradlew runServer` (Minecraft EULA에 직접 동의해야 함)
- 게임 테스트는 일반 월드를 건드리지 않도록 `run-gametest-homenet`, `run-gametest-standalone`에서 실행합니다.
- `build`의 JUnit 단계에는 테스트가 없습니다. 검증은 별도의 실제 Forge **GameTest 서버**에서 실행합니다.
- 리소스 재생성: `python3 scripts/generate_assets.py`. 생성된 원본 픽셀 텍스처·모델·언어·제작법을 저장소에 포함했습니다.

[검증 결과](docs/VALIDATION.md)를 참고하세요. 0.3.0에서는 실제 그래픽 클라이언트를 실행해 설정·기기·문 외형·PNG/JPEG 가져오기·그리기·서버 저장을 검증했습니다.
간헐적 튕김은 사용자의 실제 crash report가 없어 원인을 확정하지 못했습니다. 확인된 공간 점유 문제를 수정하고,
비정상 저장값·큰 이미지·동적 텍스처·이동 패킷의 안정성 제한을 추가했습니다.
